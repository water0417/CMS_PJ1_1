# 问达 · ASKWELL

基于 **MongoDB + NestJS + Vue 3** 的问卷系统课程项目。当前只使用一套**灰阶杂志风前端**，包含登录、工作台、问卷编辑、填写和统计页面。

## 先看这里：如何启动

**准备：安装 Node.js 22 LTS（含 npm）、Docker Desktop；先打开 Docker Desktop，使用 Linux containers。**

在项目根目录（能看到 `package.json` 的目录）打开 PowerShell。直接下载 ZIP 的同学先解压，进入解压后的项目目录。

### 第一次运行：复制下面的命令依次执行

```powershell
npm.cmd ci
docker compose up -d --wait
npm.cmd run db:init
npm.cmd run build
npm.cmd run seed
npm.cmd start
```

**启动后，在浏览器打开：http://127.0.0.1:3000**

`npm.cmd start` 运行期间请保留终端。浏览器页面可以随时关闭，不影响已发布问卷；停止后端或数据库则暂时不能填写。

### 人工测试演示账号

`npm.cmd run seed`（等同于 `npm.cmd run seed:manual`）初始化你提供的人工演示数据：创建者 `user`，问卷 **《今天是什么颜色呢》**，内容采用已确认的最新9题草稿。

| 填写者 | aaa    | aaa12345 |

### 以后再次启动

已完成安装和构建后，在同一目录执行：

```powershell
docker compose up -d --wait
npm.cmd start
```

仍打开 **http://127.0.0.1:3000**。更新代码后先执行 `npm.cmd ci`、`npm.cmd run build`，再重新启动应用。

Windows 也可使用启动脚本：首次执行 `./启动项目.ps1 -Install -Demo`，以后执行 `./启动项目.ps1`。若脚本被系统策略阻止，使用上面的逐条命令即可。

**遇到问题：** MongoDB 使用项目专用端口 **27018**，必须为副本集；不需要关闭本机27017的独立实例。3000端口被占用时先停止旧项目实例，不要重复启动。更多配置和排错见 [运行与操作指南](docs/运行与操作指南.md)。

## 页面与操作指南

操作顺序：**登录 → 新建问卷 → 编辑并保存 → 发布并复制链接 → 登录填写 → 提交 → 查看统计**。

### 1. 登录后进入工作台

使用上面的演示账号或点击“立即注册”。工作台可新建、搜索及筛选自己的问卷；草稿点“继续编辑”，已发布问卷可“分享”和“统计”。

![杂志风工作台：新建、草稿、分享与统计入口](design-preview/migrated/workspace.png)

### 2. 编辑题目、保存并发布

左侧选择题型或定位题目，右侧编辑内容和校验。点击“保存草稿”，完成后“发布问卷”。通用／分支标识由跳转规则自动计算，不需要显示条件开关：规则目标为分支题，未命中时顺序跳过分支题。

![杂志风编辑器：题型、目录、分支标识与发布入口](design-preview/migrated/system-routing-unified.png)

### 3. 分享、填写和统计

从工作台复制填写链接，填写者登录后按题目确认答案。返回查看不清空，确认改答后由后端重算路径；完成后点击“提交答卷”。创建者从工作台“统计”查看正式答卷的汇总和逐题结果。

![杂志风统计页面：提交数和逐题分析](design-preview/migrated/statistics.png)

以上为现有项目截图，账号、题目和数量是截图时的演示数据，不要求与首次初始化完全相同。**完整图文步骤见 [前端页面操作指南](docs/前端页面操作指南.md)**；图片作为操作示意，不代表本轮用户人工测试已完成。

## 测试分为两部分：系统自动化与人工验收

### 一、系统自动化测试（脚本＋API）

先启动数据库并初始化副本集，再在项目根目录执行：

```powershell
npm.cmd test
npm.cmd run build
npm.cmd run test:integration
```

- `test`：领域规则＋前端分类测试。
- `build`：前后端类型检查与构建。
- `test:integration`：自动启动3101临时API，使用真实MongoDB的独立 `survey_studio_test_*` 数据库，结束后关闭临时API；不清空正式数据。逐组结果写入 `test-results/integration.json`。

本次推送前完整回归为 **55/55项自动测试通过、28/28组API＋真实MongoDB测试通过、构建通过**；日期、对应版本及证据见 [测试记录](docs/测试用例与结果.md)。历史结果不等于每次改动都已重新执行；本轮文档核对结果见AI日志。

### 二、人工测试（你的问卷与账号）

使用上述 `user`、`aaa`～`eee` 和《今天是什么颜色呢》，验证界面、分支、校验、返回修改及提交统计。问卷定义、测试账号、可填写的记录表见 [人工测试数据与记录](docs/人工测试数据与记录.md)。目前5份填写及统计结果已记录并复核；错误输入人工证据待补，与自动化通过数分开记录。

演示初始化的独立数据库验证可运行 `npm.cmd run test:seed:manual`，它验证初始化脚本，不代表人工验收通过。

## 功能与设计

- 用户注册、Cookie会话、所有者隔离；全部业务数据保存在MongoDB。
- 草稿、发布快照、截止时间、关闭收集和独立分享链接。
- 九种题型：单选、多选、文本、数字、矩阵单选、排序、时间、滑动评分、色彩。
- 单选、多选、数字跳转，首条命中；自动专属分支，支持循环及END。
- 返回查看保留答案、改答清理失效分支、候选答案隔离；最多200次确认，180次提醒。
- 必须登录，可按配置匿名；默认每账号一份，可允许多次。
- 保存恢复、乐观锁、MongoDB事务、并发限次、幂等提交及聚合统计。

当前系统采用统一分支机制，归档快照保留旧规则解释，不是两套前端。系统维护迁移见 [统一分支机制迁移](docs/系统统一分支机制迁移.md)，日常使用不需要逐份点击升级。

## 开发者配置（正常使用可跳过）

`npm.cmd run dev` 启动**同一套杂志风前端**的开发模式：网页 http://127.0.0.1:5173，代理后端3000；仅用于热更新调试。不要同时运行 `npm.cmd start`，避免重复占用3000。普通演示统一使用前述3000入口。

默认数据库：`mongodb://127.0.0.1:27018/survey_studio?replicaSet=rs0&directConnection=true`。API读取 `apps/api/.env`，seed读取根目录 `.env`；也可以通过当前PowerShell环境变量统一设置MONGODB_URI、PORT，模板见 `.env.example`。项目通过锁文件安装本地Node22运行时。

关闭页面不会停止收集；系统中的“关闭问卷”才会停止收集。Ctrl+C停止应用；`docker compose stop`停止数据库但保留数据，避免执行删除命名卷的命令。当前服务仅供本机访问，127.0.0.1链接不能直接分享给其他设备。
