# 系统统一分支机制迁移

2026-10-22，按用户最新要求，取消逐问卷升级 UI，统一升级系统。此决策取代上一轮“旧草稿必须逐份预览和确认”的产品流程。

## 本机实际执行结果

- 正式数据库 `survey_studio` 的 4 份问卷草稿全部设为 `exclusive-branches-v1`。
- 1 份当前发布问卷生成新的发布快照并切换当前版本；原快照保留用于历史答卷追溯。
- 已存在的 9 份答卷全部通过新路线兼容校验，保留 9 份，清理 0 份。
- 无需重置任何进行中的填写。账号、题目内容、公共链接、截止时间和权限设置保留。
- 数据库只读复核：所有草稿和所有当前发布版本均为新机制，答卷数量仍为 9。
- 前端移除升级按钮、确认弹窗、预览状态和对应样式；通用／分支标识、实际入口和即时分类保留。
- 浏览器登录后检查原旧草稿：直接显示专属分支模式，无升级操作。正式预览服务已重启：http://127.0.0.1:3000/。

## 迁移实现与冲突处理

新增 `scripts/migrate-system-routing.ts`。维护时先停止 API，然后执行：

```powershell
npm.cmd run routing:migrate
npm.cmd run routing:migrate:apply
npm.cmd start
```

默认只读预演；`--apply` 才修改数据库。使用 MongoDB 事务，写入前生成 BSON 可恢复备份。当前发布版本先验证定义，若没有通用入口则回滚并报错，不篡改题目或强行发布。未完成的空草稿可以迁移模式，后续仍需编辑为合法定义才能保存／发布。

发布快照不原地改写：创建新快照后切换当前版本。兼容的历史答卷保留原版本绑定。若历史答卷按新规则校验冲突，则按本次用户授权清空该问卷的填写记录、答卷和重复提交占位，其他问卷不受影响；旧收据自然过期，且无法操作已删除的填写。仅存在进行中旧填写且分支语义改变时，重置这些进行中的填写；无分支时续接新版本并提升填写 revision。原始数据均在迁移备份内。本机此次没有触发清理。

`schemaVersion` 仍为 1。领域层保留旧机制解释以读取归档快照；这不代表当前问卷仍需选择或手动升级模式。原升级 API 仅作为历史兼容接口保留，前端不再调用。
