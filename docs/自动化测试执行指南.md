# 自动化测试执行指南

测试现分为两类：本文为系统自动化（脚本＋API），用户人工验收见 [人工测试数据与记录](人工测试数据与记录.md)。`seed`默认初始化人工演示，原系统九题型样本使用`seed:system`；自动化API测试自建独立库，不依赖两组演示数据。可额外执行 `npm.cmd run test:seed:manual` 验证初始化保护策略，不计为人工验收。

## 环境与执行步骤

在项目根目录安装依赖，启动项目MongoDB副本集；测试连接真实MongoDB，不使用内存数据库代替。

```powershell
npm.cmd ci
docker compose up -d --wait
npm.cmd run db:init
npm.cmd test
npm.cmd run build
npm.cmd run test:integration
```

1. `npm.cmd test`：Node测试运行器执行engine、branch-routing及frontend-routing三个测试文件，输出每条用例及总通过数。
2. `npm.cmd run build`：TypeScript及Vue类型检查、前后端构建，退出码0表示成功。
3. `npm.cmd run test:integration`：自动在3101启动临时API，自动注册独立测试账号、创建问卷、发HTTP请求并核对数据库。无需人工用Postman逐个点击。
4. 检查终端是否全部PASS及退出码0，读取 `test-results/integration.json` 的执行时间、独立数据库名和各组结果。测试结束关闭临时API，保留测试库供核对，不删除正式数据。

3101应空闲，MongoDB必须支持事务。自定义测试连接通过TEST_MONGODB_URI；脚本会替换数据库名为survey_studio_test_*。不要把测试失败日志当成通过记录。
