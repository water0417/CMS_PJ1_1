# 专属分支与规则语义模式升级

日期：2026-10-22。本说明以最新用户决策为准，取代已中断、未交付的独立显示条件方案。**不增加显示条件配置或开关。**

## 一、实际推进规则

新模式名称为 `exclusive-branches-v1`。从完整问卷的全部 `jumpRules` 收集非 `END` 的目标 ID：这些题是分支题，其他题是通用题。分类由配置决定，即使本次没有命中某条规则，它的目标仍是分支题。

- 开始：进入题序中的第一道通用题，没有通用题则保存/发布校验返回 `NO_ENTRY`。
- 成功确认答案：依配置顺序判断，第一条命中即生效；命中题目则直接进入，命中 END 则直接结束。
- 未命中：寻找当前题后面的第一道通用题，跳过所有分支题；没有通用题就结束。
- 可选题为空：不触发条件规则，采用同样的通用题后继。
- 分支回答后也用相同算法，不自动组成题组；连续分支必须配置明确跳转。

任何被指向的题均不允许顺序进入，不提供例外。自动跳过分支不消耗次数；确认一次计一次，内部路径重算不重复计数。200次上限及180次提醒保持。

统一实现 `createRoutingPlan` 同时给出分类、入口、默认后继、实际后继及可能后继。开始、正常推进、改答重算、候选保留的可达性搜索、结构出口检查和最终提交均使用该计划，没有第二套旧顺序算法。

## 二、新旧模式与兼容

| 标记                  | 解释                                                   |
| --------------------- | ------------------------------------------------------ |
| routingMode 缺失      | 永久按 legacy-v1 解释，不根据部署日期或当前默认值猜测  |
| legacy-v1             | 保留旧算法：未命中时进入数组下一题，包括被规则指向的题 |
| exclusive-branches-v1 | 新算法：未命中时跳过所有分支题                         |

模式属于 `Definition.routingMode`，发布时与完整定义一并进入不可变 `survey_versions.definition`。填写过程和答卷通过 surveyVersionId 固定版本；每次读取/推进仍读取该版本，不用后来编辑的草稿或全局新默认值。

新创建草稿由服务端写入新模式。旧草稿不静默升级。普通保存省略模式时保留原模式，以兼容现有编辑器；显式改成不同模式返回409，必须通过升级接口。不能用提交请求里的 routingMode 覆盖发布版本。

`schemaVersion` 仍为1：题型、答案、路径、确认集合及候选答案结构没有改变。本次变化是解释跳转规则的语义，用独立模式标记隔离，而非统一升级答案结构。旧发布快照、旧答卷、旧填写过程都不批量改写。

已中断方案的 displayCondition 不再执行，保存/发布若携带此字段会明确拒绝，避免默默忽略后造成错误理解。实验性显示条件测试产物只作为中断过程记录，不代表当前功能；当前权威结果为 branch-routing-*。

## 三、业务示例与差异

完整可提交定义见 [示例 JSON](examples/branch-routing.json)。Q2选A跳Q3，选C/D跳Q4，其余没有规则。

| Q2回答 | 新模式      | 旧模式，同样的跳转配置 |
| ------ | ----------- | ---------------------- |
| A      | Q1→Q2→Q3→Q5 | Q1→Q2→Q3→Q4→Q5         |
| B      | Q1→Q2→Q5    | Q1→Q2→Q3→Q4→Q5         |
| C/D    | Q1→Q2→Q4→Q5 | Q1→Q2→Q4→Q5            |

新模式的Q3/Q4为分支，Q1/Q2/Q5为通用。不必给Q3每个选项补到Q5的规则。相同定义在缺标记的旧快照中仍有意保留旧路线，这属于兼容结果，不是测试失败。

## 四、已有草稿如何升级

登录为创建者后：

1. `GET /api/surveys/:id/routing/upgrade-preview`，查看 before、after、revision、canUpgrade、errors、newlyExclusiveQuestionIds 和 warning。
2. 展示升级后完整分支列表和实际入口。任何有入边的题都将无法顺序进入；即使创建者原本视其为通用题也无例外。
3. 用户明确确认后，调用 `POST /api/surveys/:id/routing/upgrade`：

```json
{
  "revision": 7,
  "targetMode": "exclusive-branches-v1",
  "acknowledgedBranchQuestionIds": ["q3", "q4"]
}
```

这里的revision和全部分支ID必须取自刚刚审阅的预览，不可照抄示例。列表不完整/有重复返回400；草稿被改动返回409，须重新预览；无入口或其他校验失败不允许升级。已发布问卷不能升级。

成功返回 `{survey, routing, upgradedFrom}`，revision+1。之后按原发布接口发布，新模式进入新快照。预览为只读；确认升级受账号归属及乐观锁保护。

早期本机只读检查发现部分草稿尚无题目。该诊断清单不上传仓库，不代表其他安装环境的状态；未自动升级正式数据。浏览器若有未保存题目，请先保存再预览。

可重复运行 `npm.cmd run routing:preview` 生成本地只读清单；这只是检查工具，不绕过登录API执行升级。环境变量/根目录.env可指定MONGODB_URI，默认读取本项目survey_studio数据库。

## 五、前端分类契约与接入状态

后端已提供：

- 创建者：`GET /api/surveys/:id/routing`。已发布问卷从发布快照计算，草稿从已保存草稿计算。
- 填写者：公开问卷接口和填写过程接口在原响应中增加 `routing`。

```json
{
  "routingMode": "exclusive-branches-v1",
  "entryQuestionId": "q1",
  "branchQuestionIds": ["q3", "q4"],
  "generalQuestionIds": ["q1", "q2", "q5"],
  "ruleTargetQuestionIds": ["q3", "q4"],
  "questions": [
    {
      "questionId": "q3",
      "title": "快乐来源",
      "kind": "branch",
      "canEnterSequentially": false,
      "referencedBy": [{ "questionId": "q2", "ruleId": "happy" }]
    }
  ]
}
```

示例questions为节选，实际返回所有题。旧模式里kind均为general、可顺序进入；ruleTargetQuestionIds及referencedBy仍说明规则入边，不能把旧模式入边直接当专属限制。

未保存编辑的本地标识计算契约：先取服务端草稿模式；只有exclusive-branches-v1才用“所有规则非END目标集合”作分支集合，否则全部按通用处理。不要根据当前答案、题型、某条规则是否可命中或是否存在入边例外改变分类。

**以下项目现已完成前端接入，详情见 [前端专属分支接入验收](前端专属分支接入验收.md)：**

1. 在编辑器/目录显示“通用题／分支题”及模式标识；修改或删除规则后重新推导标识。
2. 为旧草稿增加升级预览与明确确认界面，显示受影响题和新入口；canUpgrade=false时展示后端错误。
3. 保存时保留routingMode，发布前说明分支不自动成组。后端已防止省略字段导致降级。
4. 填写只采用服务端currentQuestionId、activePath、ready和navigationMode，不在浏览器再走数组下一题；180次提醒沿用当前页面。
5. 不增加显示条件设置开关、不增加“这题仍可顺序进入”的例外。

前端已提供分类徽标、实际入口和旧草稿升级弹窗，填写以服务端状态为准。历史浏览器验收及未覆盖场景见上述记录；本次发布不代表重新执行了全部浏览器验收。

## 六、改答、循环与提交

查看只移动游标，不能返回有效路径外的题。确认改答后，按固定模式从入口重新演算，保留新路径中的合法答案；不能再访问的分支答案清除。新未处理题必须补答或明确跳过，潜在汇合答案继续隔离，只有实际进入才恢复。候选值不会让未命中的分支被顺序访问。

实际路径重复到前缀题目时保持原截断：保留目标题值，清除其后和候选，把目标标为未确认。主动查看不是推进，不重置次数；同路改答复用尾部不算循环。

最终提交读取后端状态，重新核验模式入口、每条有效后继、确认集合、END、答案及候选区。未入路径的分支不校验必答，也不能写入答卷或统计。权限、匿名、占位、事务、乐观锁及幂等逻辑保留。
