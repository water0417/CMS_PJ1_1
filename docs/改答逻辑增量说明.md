# 返回查看与确认改答：增量修改说明

日期：2026-10-22。基于现有系统增量修改，保留用户已设计的前端样式、集合结构、发布版本、答卷和安全机制。

## 需求与行为

**用户提出普通改答不应清除无关联答案，因此将主动返回修改与条件循环跳转分开处理。**

| 操作                     | 新行为                                                            |
| ------------------------ | ----------------------------------------------------------------- |
| 返回 Q1 查看，不确认改答 | 原答案、路径、完成状态和推进次数均保留，只改变查看游标与 revision |
| 无跳转，Q1 改答          | Q2/Q3/Q4 保留，重算至 END，无需逐题重填                           |
| 有规则但实际路径不变     | 保留全部后续有效答案                                              |
| Q1→Q2→Q3→Q4 改为 Q1→Q4   | 清除 Q2/Q3，保留 Q4                                               |
| 新分支尚未回答           | 停在首个待确认题，拒绝提交；可能汇合的旧答案暂存隔离候选区        |
| 补答后汇合到旧路径       | 验证并复用对应答案，清除不再有效的其他候选                        |
| 条件跳转真正形成循环     | 保留目标题旧值供填写，截断其后路径与答案，目标题须重新确认        |
| 达到 200 次              | 仍可查看，不允许第201次确认；已完成路径可提交后端原答案           |

## 状态设计

`currentQuestionId` 现在只表示正在查看或填写哪题；有效路径的末端由 `activePath` 末项表达，完成则为 END。`ready` 独立表示后端保存的路径已完整到 END，而不是“当前页面必须显示完成页”。

新增四个字段：

| 字段                        | 用途                                           |
| --------------------------- | ---------------------------------------------- |
| navigationMode              | answer 正常填写；review 主动查看/改答          |
| confirmedQuestionIds        | 有效路径中已确认题，包括明确跳过的可选题       |
| pendingAnswers              | 新分支尚未决定时，隔离保存可能重新汇合的旧答案 |
| pendingConfirmedQuestionIds | 候选确认记录，也保存可选题明确跳过的事实       |

有效答案只放在 `answers`，未决定分支的候选不能提交或统计。遇到未答题就暂停实际路径，不能用未答题的默认值猜测规则。候选保留采取结构可达性的保守判断；实际补答后再沿具体答案决定恢复还是清除。这样既不提前删除可能重用的末端答案，也不把未经确认的新分支视为完成。

旧记录读取时补齐字段：已完成路径全部视为已确认；进行中的旧路径除末端外视为已确认。返回/改答后按正常乐观锁写入新结构。数据库对新增字段约束类型，未把它们设为旧文档必填。不需批量迁移；旧版已经清除的数据不会凭空恢复。

## 代码与接口

- `domain.ts`：rewind 不再删除；advance 通过已保存答案重算路径；实际循环独立截断；validateFinal 检查确认集合、候选区、每条路径边和结束状态。
- `service.ts`：新建和读取填写时规范化状态。已有归属、revision、事务、占位和幂等流程保留。
- `database.ts`：新增状态字段的集合验证，保持旧文档兼容。
- `Fill.vue`：仅调整填写交互，保留现有设计；移除“返回即清空”确认框；完成页可选择任意题查看；确认改答后使用后端的新状态。

接口路径及请求字段不变：back 仍提交 revision/questionId；advance 仍提交 revision/answer；submit 仍提交 revision。

独立前端须同步：

1. 根据 currentQuestionId 和 navigationMode 显示返回题；不要用 ready 单独控制整个页面，否则 ready=true 的查看状态会立即被完成页覆盖。
2. 返回不修改本地路径/答案，只应用 back 返回的状态；后端 revision 仍会增加。
3. 改答须通过 advance 确认，再应用完整返回值。可能直接回 END，也可能进入未答的新分支，不能自行认定下一题。
4. pendingAnswers 不作为有效答案；不能靠 answers 有值来判定题目已经确认。
5. 预览题目不会保存输入；“返回提交确认”展示的是后端已确认数据。提交始终使用服务端保存的答案。
6. 无论返回多少次，都不得将 transitionCount 置零；确认操作仍受200次上限限制。
