# 前端专属分支接入验收

日期：2026-10-22。基于现有前端增量修改，保持灰色杂志风、字体、固定编辑框架、连续题目编辑和既有账号／提交流程。

## 实现

- 编辑目录和题目卡片显示通用／分支标识；卡片列出来源规则，并解释仅条件跳转可进入。
- 编辑器显示模式、实际入口及服务端／未保存预览来源。无通用题显示 NO_ENTRY。未保存规则通过共享的 routingMetadata 契约即时计算，不执行填写导航。
- 读取 GET /surveys/:id/routing；保存后用返回的草稿和重新读取的 routing 更新。缺省模式仍是 legacy-v1，不写新默认值；schemaVersion 不变，没有显示条件控件或 displayCondition 字段。
- 旧草稿升级前要求先保存，展示服务端预览的新旧模式、入口、完整分支列表、新增专属题和警告。勾选审阅后才能确认；canUpgrade=false 时禁用。使用预览 revision 和去重的完整分支 ID（无分支传 []）。
- 升级冲突／确认集合不匹配重新获取预览并撤销勾选；服务端无效升级原因显示在弹窗。成功使用返回 survey、routing、revision 刷新。已发布问卷无升级操作。
- 填写使用服务端固定版本 routing，所有推进／返回／改答／提交均调用后端。当前题由 currentQuestionId 决定，返回只使用 activePath，不按题目数组推进。
- ready 与查看游标保持独立；不读取 pendingAnswers 来判定完成。汇总按 confirmedQuestionIds 显示确认状态，180 次提示、200 次禁用继续确认，提交仍交给后端校验。冲突提供显式读取最新状态入口。

## 验收对应结果

| 要求                  | 实际验证与结果                                                                                                                                                                                         |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1. A/B/C/D 路线       | 规则和 API 四条独立路线通过；浏览器从 A 完成后依次改答 B、C、D，观察到 A=Q1/Q2/Q3/Q5，B=Q1/Q2/Q5，C、D=Q1/Q2/Q4/Q5                                                                                     |
| 2. 即时分类和入口     | 浏览器将 Q2 首条目标从 Q3 改成 Q1，Q1 立即变分支、Q3 变通用、入口变 Q2；删除该规则后入口恢复 Q1。另有响应式测试通过；保存后显示服务端分类                                                              |
| 3. 连续／尾部分支     | 规则和真实 API 测试通过；浏览器 A 回答 Q3 后直接到 Q5，没有顺序进入 Q4                                                                                                                                 |
| 4. 首题为分支         | 规则及 API 验证从实际通用入口开始；浏览器编辑预览即时显示 Q2 入口                                                                                                                                      |
| 5. 无通用题           | 规则及 API 拒绝保存／发布；前端分类测试返回 null 入口；浏览器旧草稿升级预览显示 NO_ENTRY，禁用勾选和确认                                                                                               |
| 6. 返回／改答／汇合   | 规则、API 通过；浏览器返回 Q2 仍有返回提交确认操作，同路确认保留尾部，B 改 C 后须补答 Q4，Q5 文本“汇合答案应保留”仍存在                                                                                |
| 7. 未访问分支不可进入 | API 越界返回／伪造路径测试通过；浏览器提交目录只含当前有效路径，B 路线无 Q3/Q4，C/D 无 Q3；填写页未新增全题目录                                                                                        |
| 8. 旧／新模式         | API 和新增前端测试通过；浏览器 legacy 草稿升级前显示旧机制且题均通用，新问卷显示专属机制                                                                                                               |
| 9. 预览与明确确认     | 浏览器预览后确认按钮初始禁用；勾选后制造版本变化，确认返回冲突、重新预览、勾选撤销；再次审阅确认后升级成功且分类刷新。无入口预览禁止升级。API 另验证不完整／重复确认集合、无分支升级、权限、旧快照不变 |
| 10. 既有功能          | 本次 26 组 API 测试覆盖登录、匿名、限次、冲突、幂等及统计隔离；浏览器使用登录和匿名测试填写。没有重写相关请求结构                                                                                      |
